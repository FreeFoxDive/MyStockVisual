# Visual 数据与画线评估（2026-09-30）

本次检查数据源适配、缓存、指标、因子库、监控与图表输入，并用离线数据和真实 ECharts 页面验证。现有方案值得保留：数据源路由与图表分离，已有超时/熔断、同参数取数合并、磁盘原子写、有限内存缓存和增量刷新。优化重点是补齐数据契约，以及减少重复派生计算。无需先换数据库或重写图表。

未做全市场在线取数或付费接口压测；供应商真实数据偏差、生产延迟和额度余量仍需抽样验证。以下区分已修复问题、离线确认的问题和容量风险。

## 本次已修复

### 后复权日K混入未复权快照

`market.fetch_kline_ex` 原先对所有复权方式都拼接实时快照，后复权历史价格可能在 100 元附近，当日原始价却只有 10 元，随后 MA/RSI/ATR 等都会受到断层影响。

后复权日K现在完整保留同口径源 bar，盘中磁盘 TTL 最长 60 秒；不再剥掉该源的当日 bar，也不再补原始快照。缓存增加 `-hfq2` 版本后缀，避免复用旧的混合价格。前复权和未复权仍按原有快照策略刷新。代价是后复权末根的实时性取决于源自身，不能把「数据口径正确」等同于「源一定实时」。

收盘前（含午休、连续竞价）写下的后复权缓存，收盘后也不改用 1800 秒 TTL。否则 14:59 的价格会在 15:00 之后最多再显示 30 分钟，漏掉收盘集合竞价。写入时刻用缓存文件的 mtime，并按 `market_hours.session_phase` 判断；收盘后写下的完整 bar 仍用休市长 TTL。

验证覆盖冷取数、磁盘命中、已有当日 bar、缺少当日 bar，以及未复权快照路径。

### CCI 平均偏差公式错误

旧实现先逐根计算 `TP - MA(TP)`，再滚动求绝对值均值，混用了不同窗口的均值。CCI(14) 首个有效值也因此延后到第 27 根。

修正为当前窗口内全部典型价格相对于同一个窗口均值的平均绝对偏差，与 [TA-Lib 官方公式](https://ta-lib.org/functions/cci.html) 一致。独立参考用例逐窗口验证；典型价格 1..14 的首个 CCI 为 123.8095238。零偏差继续返回 NaN，保持现有显示契约。计算用 `sliding_window_view` 向量化，避免全市场因子构建时每个窗口调用一次 Python；窗口内的 NaN 仍只让受影响的窗口失效。

图表与因子构建共用这个函数，因此两条路径都得到修复。已经落盘的因子快照不会自动改写，历史 CCI 条件选股结果也不会自动重算；需要新构建后才获得新公式结果。本次没有重建因子库或消耗全市场额度。

### 顶部滑杆误拖动与平板定位

原有 `moveOnMouseMove` 只控制 inside dataZoom，不能阻止 slider 自身命中；主图上沿靠近滑杆时画线会被接管。触屏原先又在按下时落点，缺少松手前微调的机会。

现在画线拥有的手势在 DOM 捕获阶段进入独立适配器，并隔离兼容 mouse/touch 事件。`dblclick` 不在屏蔽列表里，双击结束折线、双击水平线改价保持可用。锁定画线时隐藏顶部滑杆，取消选中或退出后恢复。主图网格以外的触摸不接管，平板可以在成交量、副图或坐标轴上捏合缩放和平移。主图上第二根手指会取消尚未确认的落点并放行后续触摸；网格内的捏合仍可能因为第一指已被画线接管而不缩放。触屏采用按住预览、拖动调整、松手确认；日期/价格读数避开手指，只有刚画完的触屏手势才自动进入编辑。端点触摸命中范围扩大并保留抓取偏移，取消手势还原端点，没有移动不生成撤销项。平板按钮扩大，长工具栏支持滚动。指针捕获失败时不接管这次按下。

真实 Chromium + 项目自带 ECharts 5.5.0 验证：顶部落点后视图范围保持不变；第二点在松手前没有提前定稿；距端点 18px 可以开始调整；系统取消恢复原坐标；正常调整产生一条撤销记录；退出后视图平移和滑杆恢复。所有 API 在浏览器验证中使用测试响应。

## 建议优先补齐的准确性问题

### P1：监控与画线复权口径仍不完整

`monitor._evaluate_trendline_monitors` 根据画线的 adjust 取日期列表，但用于比较的仍是原始 `last_price`；取同口径日期不能把实时价转换为同口径价格。后复权水平线 100、原始现价 10 的场景会被误判跌破。此次日K修复不会同时修复监控价格比较。

建议以明确、同日的复权映射把现价与线值统一后再比较；缺映射时返回不可评估状态。不能靠历史末根与实时价的比例盲算，因其可能同时含行情涨跌和源滞后。

此外画线存储隔离键只有用户、标的、周期，普通画线没有统一记录复权方式。切换复权后锚点价格照搬；除权后前复权历史价格变化也可能使旧画线失去原意。建议给画线补充复权口径及基准，再设计转换/迁移规则，并兼容既有数据。

### P1：分钟新鲜度检查只挡住极旧数据

`kline_source._minute_fresh` 的默认阈值为 30 个自然日，且只判断 age <= threshold。离线验证确认：落后一周的分钟序列通过，未来一天的序列也通过。

建议保留停牌、盘后和节假日规则，另增加按标的市场、交易日历、周期及交易阶段推导的末根时间检查，并拒绝超出合理时钟容差的未来数据。响应应区分实时、历史可用和滞后；不要把所有休市/停牌数据简单判成故障。

### P1：统一化缺少唯一时间戳与 OHLC 校验

`market._normalize` 会保留重复索引，缺失 OHLC 列被补为 0。离线输入含重复日期、仅含 close 的六行数据，能够作为标准序列返回，且 open 全为 0。重复根会扭曲指标窗口，零价会影响图表范围与 ATR。

建议在源适配器和磁盘读路径共用验收函数：稳定排序、明确重复根的取舍策略、校验有限 OHLC 与高低边界、校验非负量额。缺失价格应拒绝或按源契约显式处理；不能静默变成 0。成交量/成交额单位也应由源声明，现有 `volume_shares_mult` 的量级推断适合作为兼容兜底，不能替代单位契约。

### P1：分钟取数缺少统一的批量额度门

`market._fetch_af_minute` 使用 `af.klines.batch([symbol])`，A 股路径没有与分钟批量额度对应的共享令牌门；港美股另有本地限速。分时退回分钟批量也会走此路径。

建议让图表、分时回退和其它分钟批量消费者统一经 `af_limits.bucket_rate("kline_minute_batch")`（27/min）取令牌，并核查多进程、其它脚本的消费。这是代码缺口，尚未在线重现 429。不能放大现有报价/盘口桶来补偿。

日K已与因子库共用 SQLite 令牌桶，方向正确；但 `SharedTokenBucket` 初始容量等于每分钟配额，允许启动突发再叠加持续补充。若上游按滚动窗口限速，仍可能超限；建议以进程间滚动窗口/均匀间隔约束取代大突发容量，先用假时钟测启动、重启和多进程竞争。

## 性能结论与优化顺序

本机 Python、1006 根合成日K、热身后 20 次测量；P95 为排序后的第 19 个样本，数据不含上游网络、磁盘解压和 JSON 编码。

- 修正 CCI 后全量指标计算：中位数 31.96ms，P95 32.85ms。
- 当前按列序列化：中位数 40.74ms，P95 44.47ms。
- 改动前测试中，逐行参考序列化中位数 80.88ms；现有按列方案已明显减轻 CPU，不建议退回 iterrows。
- 此样本的完整 bar 列表 JSON 约 1.03MB，包含全部指标；实际响应大小随数据和数值精度变化。

优先处理以下路径：

1. **复用历史序列与派生结果。** 交易日日K跳过完整 API 内存缓存，即使磁盘命中仍会解压、创建 DataFrame、重算约千根指标。tail 缓存已复用 10 秒结果，但并发冷 miss 仍可能重复计算。建议先合并派生计算，再缓存已确认历史与基准指标状态；当天改动从基准状态重算，不能在每个快照上反复累加 OBV/EMA。必须用全量计算作基准覆盖跨日、复权变化、历史纠错和 warmup。
2. **降低首屏响应成本。** 核查部署代理的压缩是否生效，测量传输字节、编码耗时及手机解析/建图时间，再考虑按需指标字段。tail 已只返回少量 bar，优先保持这条增量路径。
3. **观察冷数据源链。** 单源默认超时 8 秒，多源连续失败会累加，冷加载的秒级抖动通常比几十毫秒 CPU 更显著。已有熔断和有界并发应保留，开启 `KLINE_PERF_LOG=1` 采集实际源、命中率、fetch/quote/indicator/serialize 耗时后再调整链顺序。
4. **按目标机器测 RSS 与多客户端。** 三类 K 线内存缓存各有 30 条完整响应，Python 对象占用会大于 JSON 字节数。SSE 在 Waitress 中每连接占一个线程，默认 8 线程/3 个 SSE 槽可保护小规模使用，但用户增加后需要测排队与轮询回退。当前没有足够证据要求迁移异步服务。

总体顺序：先统一价格、时间与单位契约，补齐额度门；再合并重复计算与优化传输；最后根据生产样本决定是否更换服务并发模型。

## 画线的后续优化

已解决本次误拖动及平板第二点定位。下一步可给趋势线/通道增加日期与价格的数值端点编辑，让精确定位不依赖手指像素；给多点工具提供触屏可见的完成/取消入口，尤其折线目前依赖 Enter/双击；给跨设备保存增加版本号和冲突提示，当前整体覆盖保存是最后写入生效。

坐标以日期加偏移保存总体合理，但分钟历史锚点滚出窗口后按相对偏移回落会改变原意。建议将无法解析的旧日期显式标为不可定位，或按需补历史窗口，而不是让旧线悄悄移动。
